## 二、依赖安装：两个坑，都已解决

### 坑 1：`better-sqlite3` 导致 server 依赖**全部装不上**（已根治）

- **现象**：`cd server && npm install` 报 `gyp ERR! find VS`，整个安装中止，`server/node_modules`
  **完全没生成**，express/cors 等一个都没有。
- **根因**：`server/package.json` 里有一个 **`better-sqlite3`**，它要本地编译 C++，本机没有
  Visual Studio「Desktop development with C++」，而 Node v24 又没有它的预编译二进制。
- **关键事实**：这个依赖**从 v1.0.13 初始提交就存在，但全仓库从来没 import 过**
  （实际用的是 `sql.js`，WASM 实现，见 `server/src/db.js`）。属于废弃残留。
- **已做的修复**：从 `server/package.json` 删除该依赖。删后 `npm install` 干净通过
  （134 包 / 19 秒 / 退出码 0）。
- **如果删除被回退**：临时办法是 `npm install --ignore-scripts`，但那是绕过，不是修复。

### 坑 2：Electron 二进制没解压（`node_modules\electron\dist` 只有一个 LICENSE 文件）（已解决）

- **现象**：`npm install` 退出码 0，但 `node_modules\electron\dist\electron.exe` 不存在；
  连跑 `node node_modules\electron\install.js` 也是**静默退出 0 且不解压**（不报错、不输出）。
- **根因**：`install.js` 走到 `extract()` 就没了下文，解压静默失败。
- **本机有利条件**：zip 早已缓存在
  `%LOCALAPPDATA%\electron\Cache\4b092cc678b6ff8448c5ab35fabca1710dccc91cfbff065280601a184126b0fe\electron-v33.4.11-win32-x64.zip`
  （115 MB，2026-09-28 下载的），**不需要重新联网下载**。
- **已做的修复**（手工两步，可重复）：
  ```powershell
  # 1) 从缓存手动解压
  $zip = "$env:LOCALAPPDATA\electron\Cache\4b092cc678b6ff8448c5ab35fabca1710dccc91cfbff065280601a184126b0fe\electron-v33.4.11-win32-x64.zip"
  Expand-Archive -LiteralPath $zip -DestinationPath node_modules\electron\dist -Force
  # 2) 补 path.txt（install.js 正常结束时会写这个，静默失败就漏了）
  Set-Content -LiteralPath node_modules\electron\path.txt -Value "electron.exe" -NoNewline -Encoding ascii
  ```
- **验证**：`node_modules\electron\dist\electron.exe --version` → `v33.4.11`；
  `require('electron')` 能解析到该 exe。

> 换电脑/重装依赖时，**这两个坑会原样复现**，照上面处理即可。

## 三、开发沙箱：唯一正确的起法

```powershell
# 后端（改后端/调 API 用，不弹 Electron）
.\scripts\dev-sandbox.ps1 server

# 完整 Electron 桌面端（真机验证用）
.\scripts\dev-sandbox.ps1 app
```

脚本做三件事：
1. 把 `DATA_DIR` 强制指到沙箱 `D:\dsh-workspace\晶振报价软件\dev-data`；
2. **护栏**：沙箱目录等于/嵌套于生产目录、或沙箱目录不存在 → 直接拒绝启动（已实测退出码 1）；
3. 清掉 `ELECTRON_RUN_AS_NODE`（见下节）。

沙箱已经备好一份**生产库副本**（856 KB，73 条报价记录），随便写、随便删，跑完从生产重新拷一份即可。

> **图片/规格书没同步**：沙箱目前只有数据库，归档图片库是空的，所以启动日志会看到
> `[archive-sync] 424 条引用找不到文件`。要连图片一起测时，把生产目录里对应的
> 图片库/规格书目录整个拷进沙箱即可（生产目录只读，拷出来不会影响它）。

### 沙箱靠什么隔离（原理）

`DATA_DIR` 是本项目**唯一**的沙箱开关（`electron/main.js` → `resolveDataDir()`）：

- 显式传 `DATA_DIR` 时优先级**高于用户配置**，不会去读 `%APPDATA%` 里指向生产的 `dataDir`；
- 同时自动 `setEphemeralConfig(true)`，所以窗口布局等**不会写**用户的真实 `user-config.json`。

## 四、本机特有注意事项

### 1. `.ps1` 脚本必须存成 **UTF-8 with BOM**

本机是 Windows PowerShell 5.1，读无 BOM 的 `.ps1` 会按 ANSI(GBK) 解码 —— 脚本里的中文会变乱码
并导致**语法错误**（`The string is missing the terminator`）。写入 BOM：

```powershell
$txt = [System.IO.File]::ReadAllText($p, [System.Text.UTF8Encoding]::new($false))
[System.IO.File]::WriteAllText($p, $txt, [System.Text.UTF8Encoding]::new($true))
```

`scripts\dev-sandbox.ps1` 已带 BOM。

### 2. `ELECTRON_RUN_AS_NODE=1` 会让 Electron 变成纯 Node（不弹窗口）

本机（DSH/agent 终端环境）里存在这个变量。它会让 `electron.exe` 退化成 Node 执行器，
表现是「命令跑了但什么都没弹」。手动开终端一般没有，`dev-sandbox.ps1` 里也已主动清掉。

### 3. `$PSCommandPath` 不能用在 `param()` 默认值里

`powershell -File script.ps1` 时 param 默认值阶段取不到 `$PSCommandPath`，会报
`Split-Path : Cannot bind argument to parameter 'Path' because it is an empty string`。
默认路径要放到脚本体里赋值（`dev-sandbox.ps1` 已这么改）。

### 4. lock 文件用的是 npmmirror 源

`package-lock.json` 里 `resolved` 全是 `registry.npmmirror.com`（虽然 `npm config get registry`
是 npmjs.org）。npm 会按 lock 里的 URL 下载，实测能通、速度正常 —— **不要去"顺手统一源"**，
否则会动到 lock 文件。

### 5. 发版用的 `gh` CLI 本机没装

`scripts\release.ps1` 靠 `gh auth token` 拿 GitHub token 建 Release。本机 `gh` 未安装
（`git push` 走 Git Credential Manager，能用）。**若要在这台机器发版**，需要先装 gh 并
`gh auth login`，否则脚本会在发布环节停下并提示手动上传。

## 六、两地接力的日常流程

```powershell
# 开工：先拉最新（接力笔记 .claude/TODO.md 已入库，能一起拉到）
git pull

# 读接力状态
#   .claude/TODO.md         → 停在哪、下次开工第一件事
#   handoff-v1.0.xxx.md     → 那一版的完整交接
#   PROGRESS.md             → 进度流水

# 开发 + 验证（一律走沙箱）
.\scripts\dev-sandbox.ps1 server      # 或 app
npm test                              # 后端 81 + 前端 3

# 收工：把接力笔记写完再提交推送
git add -A && git commit -m "docs: ..." && git push
```

**搬迁一律用 `git clone`，不要拷文件夹**（原目录 14.2 GB 里绝大部分是 `dist-exe/` 历史安装包）。
